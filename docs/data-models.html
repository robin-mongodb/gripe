Gripe data models: one domain, modeled twice

The same payments domain behind one Store interface, shaped idiomatically per backend. PostgreSQL normalizes with foreign-key integrity (store/postgres/migrations/00004); MongoDB embeds where access patterns are single-document (store/mongo/store.go). Money is int64 minor units everywhere.

MongoDB — collections with embedding (5 collections)

Refunds live inside their payment (bounded array: Σ refunds ≤ amount) so a refund is one atomic document update. Balances are a currency-keyed map inside the merchant, so a settle is one $inc. No FKs — integrity comes from the Store's implicit onboarding.
